# Sift

Know exactly what's in it before your kid watches it.

Parents approve YouTube channels and videos. Kids get a locked player that shows only those. Every video gets a **content card** — synopsis, age fit, pacing, and twelve specific concerns (monsters, loud sounds, yelling, sad themes, toy pushing…) each with a timestamp and one-line evidence — generated by an AI reviewer that watches the whole video, then confirmed or corrected by other parents.

The review database is the product. The app is how it gets built.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
```

That's it. With no API keys the app runs on a local JSON store (`data/db.json`, seeded from `data/seed.json`) with a few sample videos and **sample** content cards (clearly labeled — they're illustrative, not real reviews).

- `/watch` — kid mode. Big tiles, locked player, auto-advances to the next approved video, hold the ⚙ for 1.5s to get the PIN screen.
- `/parent` — dashboard. PIN is `1234` until you change it. Paste a YouTube link or `@handle` to approve, toggle channels, set filters.
- `/parent/video/<id>` — the content card, with 👍 / ⚠ one-tap parent confirmation.

## Review real videos

```bash
cp .env.example .env.local      # add GEMINI_API_KEY
npm run review -- https://www.youtube.com/watch?v=XqZsoesa55w https://youtu.be/yCjJyiqpAuU
npm run review -- --all          # review everything that only has a sample card
npm run review -- --file urls.txt
npm run review -- --channel @SuperSimpleSongs --max 5   # needs YOUTUBE_API_KEY
```

The reviewer sends the public YouTube URL to Gemini (no downloading), forces a JSON schema, and writes the card. `src/lib/reviewer.ts` has the prompt and taxonomy; `src/lib/types.ts` has the twelve tags.

## Go multi-family (Supabase)

With Supabase configured the app switches from "one family, PIN lock" to real accounts:
parents sign in by magic link, each account owns a family, and kid devices are paired with a
6-digit code (they never sign in).

1. Create a Supabase project. In the SQL editor, run `supabase/migrations/0001_init.sql`,
   then `0002_format.sql`, `0003_auth_devices.sql`, `0004_requests.sql`, `0005_open_mode.sql`, `0006_kids_only_search.sql`, `0007_async_checks.sql`, `0008_push.sql`.
2. Settings → API Keys: put the Project URL, publishable key, and secret key in `.env.local`
   (see `.env.example`). The app switches stores automatically.
3. Authentication → URL Configuration: add your site URL(s) (e.g. `http://localhost:3000` and your
   Vercel URL) to the redirect allow list so magic links can land on `/auth/callback`.
4. `npm run seed` loads the sample channels/videos/cards, then `npm run review -- --all` replaces
   the sample cards with real reviews.

5. Authentication → Email Templates → **Magic Link**: replace the body with something like

   ```html
   <h2>Your Sift sign-in code</h2>
   <p style="font-size:32px;letter-spacing:.3em"><b>{{ .Token }}</b></p>
   <p>Or open this link on the same device: <a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=magiclink">Sign in</a></p>
   ```

   The code is what people actually use on phones; the link is a fallback that doesn't depend on which browser opens it.

Flow: parent opens `/login` → types the emailed code → `/parent`. Parent → **Devices** → make a code.
Tablet opens `/pair` → types the code → lands in kid mode, permanently.

## The pipeline

Approving a channel pulls its 20 most recent uploads onto the kid's home screen. A nightly
job (`/api/cron/sync`, scheduled in `vercel.json`; set `CRON_SECRET`) refreshes every approved
channel and pre-reviews up to 20 new videos, so new uploads arrive already carded. The parent
dashboard has a "Review next 5 now" button; `npm run pipeline` does the same from a terminal.

## Nightly discovery

`data/discovery.json` lists well-known kids channels. `/api/cron/discover` (daily, 11:00 UTC) refreshes their newest uploads and reviews up to 25 short videos within a 4-minute budget, so every family's Search gets them as instant "Play". Run by hand with `npm run pipeline -- --discover [--max 25]`. Edit the list freely — unknown handles are skipped.

## The feedback loop

On every content card a parent can say the card is accurate, too strict or too lenient, vote 👍/👎 on each tag the AI raised, mark tags it missed, and vote on the age range. That feedback does three things:

1. **Gating, immediately** — enough "missed" votes block the tag for families that filter it; enough "over-called" votes neutralize an AI tag.
2. **Calibration notes, nightly** — `learnFromFeedback()` distils recent disputes into ≤15 general guidelines (versioned in `reviewer_notes`) that are appended to the reviewer's system prompt. Parents can edit them by hand at `/parent/reviewer`.
3. **Re-review** — disputed cards get a second look with the dispute as context (max two revisions per card, so it can't ping-pong).

`/parent/reviewer` shows agreement rates per tag, the current notes, and recent disputes. Run migrations `0009_feedback.sql` and `0010_usage.sql` (token usage + cost per card; the Reviewer page shows spend, and nightly discovery stops at `DISCOVERY_BUDGET_USD`).

## Reviewer evals

`npm run eval -- --pin` freezes every parent-confirmed verdict into `data/eval.json` (commit it — it's the golden set). `npm run eval` re-reviews those videos with the current calibration notes and scores tag precision/recall, format, age and the gate decision; `--notes none` is the baseline, `--notes 3` a specific version, `--compare a.json b.json` diffs two reports. Run it before trusting a new notes version.

## Kid profiles

Each kid (`profiles` table, migration `0011_profiles.sql`) has their own viewing mode, filters, daily check limit and screen-time settings; the family shares the PIN and crowd threshold. The dashboard's filter card has a tab per kid; `/parent/kids` adds and edits them. On a shared TV the viewer shows "Who's watching?" when there's more than one kid and remembers the pick in a cookie; the avatar in the header switches. Watch history, checks and requests are tagged with the profile. Pairing codes are now 8 digits.

```
data/seed.json      sample data (db.json is gitignored)
```
