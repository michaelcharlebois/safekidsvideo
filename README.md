# Sift

Know exactly what's in it before your kid watches it.

Parents approve YouTube channels and videos. Kids get a locked player that shows only those. Every video gets a **content card** — synopsis, age fit, pacing, and twelve specific concerns (monsters, loud sounds, yelling, sad themes, toy pushing…) each with a timestamp and one-line evidence — generated by an AI reviewer that watches the whole video, then confirmed or corrected by other parents.

The review database is the product. The app is how it gets built.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
```

That's it. With no API keys the app runs on a local JSON store (`data/db.json`, seeded from `data/seed.json`) with a few sample videos and **sample** content cards (clearly labeled — they're illustrative, not real reviews).

- `/watch` — kid mode. Big tiles, locked player, auto-advances to the next approved video, hold the ⚙ for 1.5s to get the PIN screen.
- `/parent` — dashboard. PIN is `1234` until you change it. Paste a YouTube link or `@handle` to approve, toggle channels, set filters.
- `/parent/video/<id>` — the content card, with 👍 / ⚠ one-tap parent confirmation.

## Review real videos

```bash
cp .env.example .env.local      # add GEMINI_API_KEY
npm run review -- https://www.youtube.com/watch?v=XqZsoesa55w https://youtu.be/yCjJyiqpAuU
npm run review -- --all          # review everything that only has a sample card
npm run review -- --file urls.txt
npm run review -- --channel @SuperSimpleSongs --max 5   # needs YOUTUBE_API_KEY
```

The reviewer sends the public YouTube URL to Gemini (no downloading), forces a JSON schema, and writes the card. `src/lib/reviewer.ts` has the prompt and taxonomy; `src/lib/types.ts` has the twelve tags.

## Go multi-family (Supabase)

With Supabase configured the app switches from "one family, PIN lock" to real accounts:
parents sign in by magic link, each account owns a family, and kid devices are paired with a
6-digit code (they never sign in).

1. Create a Supabase project. In the SQL editor, run `supabase/migrations/0001_init.sql`,
   then `0002_format.sql`, then `0003_auth_devices.sql`.
2. Settings → API Keys: put the Project URL, publishable key, and secret key in `.env.local`
   (see `.env.example`). The app switches stores automatically.
3. Authentication → URL Configuration: add your site URL(s) (e.g. `http://localhost:3000` and your
   Vercel URL) to the redirect allow list so magic links can land on `/auth/callback`.
4. `npm run seed` loads the sample channels/videos/cards, then `npm run review -- --all` replaces
   the sample cards with real reviews.

Flow: parent opens `/login` → email link → `/parent`. Parent → **Devices** → make a code.
Tablet opens `/pair` → types the code → lands in kid mode, permanently.

## Layout

```
src/app/            routes (parent/, watch/, unlock/) + server actions
src/lib/types.ts    domain types + concern taxonomy
src/lib/reviewer.ts Gemini video reviewer
src/lib/queries.ts  library/feed aggregation + filter logic
src/lib/db/         Store interface, local JSON + Supabase implementations
src/lib/youtube.ts  URL parsing, oEmbed / Data API metadata
scripts/review.ts   reviewer CLI
supabase/           schema
data/seed.json      sample data (db.json is gitignored)
```
